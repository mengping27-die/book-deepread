# book-deepread

**让 AI 真正读完一本书，而不是假装读完。**

一个 Claude Code skill + 一套配套规范。装上之后，Claude 遇到「精读某本书」「把这本书读进知识库」「写/检查精读笔记」「给外部 AI 写精读任务书」这类整本书级别的任务时，会自动按这套规范执行。

## 装法

```bash
cp -r book-deepread ~/.claude/skills/
```

装完重开一个会话，它应该出现在可用 skill 列表里。

## 里面有什么

| 文件 | 作用 |
|:--|:--|
| `SKILL.md` | **skill 本体** —— 触发条件 + 三条工作路径 + 硬约束 |
| `docs/精读指令.md` | **质量**规范 —— 「正文」（零~八条）发给外部 AI；「附录」A/B/C 自己留着用 |
| `docs/精读模板.md` | **格式**模板 —— 标准版 / 简版 / 枚举型章节 / 详略分级 |

## 它解决的问题

用 AI 读书，最大的风险不是它读错，是它**让你以为读全了** —— 字数够、模块齐、小标题漂亮，但你翻回原书一查，页码是编的，最关键的一章一字未读。

这套规范是对着这个问题设计的。

## 设计要点

**① 装懂探测器：存疑清单 + 覆盖度自曝。**

每篇精读必须交代两件事：**哪里没把握**（页码不清、认不准的字、概念不确定）和**哪里跳过了**（略过哪些章、为什么略）。

第 1 条为什么有用：**任何一本书都不可能零疑问**。一份"毫无存疑"的精读稿，就是在装懂。这比数字数可靠得多。

**② 详读的该是骨头，不是好啃的肉。**

实测发现，外部 AI 会**系统性地跳过两种章**：定义密集的地基章（没故事，难写）、逐条并列的清单章（又难又容易错）。而去详读有现成案例、好摘的章。

注意它的选择不是"从头读到哪算哪"，而是**挑顺手的** —— 全书第一章可能只做了概述，中间几章反而详读。

所以验收时要问一句：**你详读的章，是这本书的骨架吗？**

**③ 反脑补的硬约束。**

很多"深度精读"提示词允许 AI 自行生成细节 —— 那等于允许编。这里的规矩反过来：**原文里没有的细节，一个字都不许补。** 宁可写「此处细节未摘录」。

**④ SKILL.md 只放指针，不搬全文。**

规范正文留在 `docs/`，skill 里只有触发条件与流程 —— 避免出现"同一份内容写两处"：两处各写一份的必然结果就是改一处忘一处。

**⑤ 详略分级，而不是每章等重。**

一本 30 章的书如果要求每章都写全套结构，结果一定是偷工。所以分「详」「略」两档：详读章写全套，略读章只写「本章一句话 + 为什么略」。并设两道闸防止"略"变成偷懒借口。

## 已知短板

**只端到端验证过一本书。**

- 「枚举型章节写法」是从那一本**倒推**出来的，**还没用它写过任何一章**
- 「略」章路径基本没走过（那本是全书通读，全是「详」）
- 配套质检脚本 `qc-deepread.ps1` 开发中出过 3 次误报，检查器本身还年轻

用它没问题，但**别当「已验证可靠」来引用**。

## 配套

质检脚本 `qc-deepread.ps1`（PowerShell）负责入库门禁：遍历精读稿目录，检查结尾三节是否齐全、有没有原文引用与定位、有没有区分【概述】与引文。**退出码 0 = 可入库。**

注意它**查不出"跳过了哪一章"** —— 那一查只能人工做。
