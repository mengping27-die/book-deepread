# 📝 精读指令（书籍精读任务规范）

> **用途**：外部 AI 精读原书时，产出直接符合标准，省掉事后返工。
> **配对**：《精读模板》管**格式**，本规范管**质量** —— 两个一起给 AI。
> **起因**：分析外部 AI 的精读产出，发现三类通病（分不清原文转述 / 不知道哪里不确定 / 爱凑数），遂制定。
> **用法**：把下面「**正文**」整段发给 AI；「**附录**」留着你自己用，**不要发给 AI**。

---

## 正文（发给 AI 的部分）

> 适用于 PDF / epub 格式书籍。产出的笔记直接进入知识库长期使用。

### 零、怎么读（开工前先看）

> 格式再好，读法不对也抓不住。**这五条比后面的格式要求更重要。**

1. **先读目录 + 各章小结，把骨架搭出来**，再回头读细节。一上来就逐字读，读到第 5 章已经忘了第 2 章。
2. **每章读完立刻合上原书，用一句话说清这一章在干什么** —— 说不出来就回去重读，别往下走。**这一句是唯一可靠的"读没读懂"检验。**
3. **盯紧章首引语和章末小结** —— 作者常把核心放在这两个地方，而不是正文中间。
4. **区分「作者的主张」和「作者的依据」** —— 前者是观点（谁都能说），后者才是可信度的来源。
5. **标出作者说「但是 / 然而 / 反直觉」的地方** —— 那往往是他最想让你记住的，也是全书最"值钱"的位置。

### 一、格式

**1. frontmatter**

> **格式长什么样 → 见《精读模板》的文件头**（那里有可直接复制的 YAML 块）。
> 这里只说各字段的**含义** —— 避免两处各写一份、改一处忘一处。

- **source**：写完整书目信息。epub 为流式排版时，"总页数"替换为"章节数"。
- **source_note**：如实写怎么读的——全文通读还是节选精读；扫描版有无 OCR、OCR 质量；用什么工具提取文字；过程中遇到的限制（如某几页模糊、缺页）。
- **confidence**：原文清晰、文字层完整→高；扫描版 OCR 错误较多→中；大量内容靠推测→低。
- **source_type**：**此字段由知识库方填写，你不用管**（避免不同 AI 造出五花八门的取值）。

**2. 正文**

- Markdown 格式，**一级标题只有一个**（即书名）。
- 章节按原书结构排列，不自行重组。
- 原书没有明确章节的，按原书条目顺序排列。

### 二、区分"原文"与"你的话"（最重要）

**引用原书文字**
- 用「」包裹，并标页码/位置。
- 格式：`原文「引用内容」(定位信息)`
- PDF 示例：`原文「气中有血，血中有气」(原书 P.310 / PDF P.319)`
- epub 示例：`原文「气中有血，血中有气」(epub 第3章·解表药 / 原书 P.45)`
- epub 无原书页码时：`原文「气中有血」(epub 第3章·解表药)`

**自己的概括归纳**
- 不要用引号。
- 加【概述】前缀。
- 示例：`【概述】本段论述了气血互生的关系。`

**严禁**
- 把概括写成引文格式（加「」或引号）。
- 把自己的话混进原文引用中。

### 三、不许猜

- **页码看不清** → 写"页码不清"，不许估数字。
- **书名/作者/年代没把握** → 写"待确认"。
- **引文里有认不准的字** → 照原样写，用【?】标出。
  - 示例：`原文「主【?】痛」(原书 P.12)`
  - 不许"按上下文改成合理的字"。
- **若确实做了校正** → 必须单独列出：改了什么、依据是什么。放在文末"存疑清单"中。

### 四、覆盖度自曝

结尾必须报告：
1. 原书共多少章节/条目。
2. 详述了哪些（列出章节/条目范围）。
3. 略过了哪些（列出章节/条目范围）。
4. 为什么略过（如篇幅过长、内容重复、原书缺失等）。

- **怎么选详略**：优先详读**全书地基 / 核心方法 / 行动指南**三类章；铺垫章、案例与别处重复的章、纯背景章可略。
  （与附录 A 第六查同源 —— 详读的该是**骨头**，不是好啃的肉。）

不许只挑好写的写，却让人以为写全了。

### 五、页码/位置定位（按文件格式分四种）

**PDF（有文字层）**
- 同时给**原书页码**和 **PDF 物理页**。
- 格式：`原书 P.xxx / PDF P.xxx`
- 说明换算关系（如"原书页码 = PDF 页码 - 31，因前置 30 页为封面/目录"）。
- 只知道一种就说明是哪种。

**PDF（扫描版，无文字层）** —— 与前一条的区别是**先判断**

- **先看有没有文字层**（决定走哪条路）：

```bash
pdftotext -f 1 -l 3 "书.pdf" - | tr -d '[:space:]' | wc -c
```

  **三种结果，走三条路 —— 别只看字数**：

  | `wc -c` 结果 | 判定 | 走哪条 |
  |:--|:--|:--|
  | 接近 **0** | 扫描版 | 本条 |
  | **非 0 且读得通** | 有文字层 | 上一条 |
  | **非 0 但读出来是乱码** | **字体缺 ToUnicode** | **下一条** |

  ⚠️ **只看字数会踩第三种**：它字数**不是 0**，但内容是垃圾。
- 扫描版的定位**改用扫描件页序**，并明确写出是哪种，例如 `（扫描件 P.xxx）`。**不得**把它写成「原书 P.xxx」—— 扫描件页序与印刷页码通常差一个前置页数，而这个差值往往查不到，写错就是伪造精确定位。
- ⚠️ **OCR 出来的文字不是可靠誊录**，因此：
  - 引用时标 `原文「…」(扫描件 P.xx · OCR)` —— **必须带「OCR」字样**，让读者知道这是机器识别的，不是誊录
  - **不能只标个别【?】字就交差**：OCR 的错字常常**看着通顺**，你根本发现不了。**必须整体声明准确率受限**
  - 尽可能做**结构坐标核验** —— 用卷 / 章 / 条目位置反查内容对不对，**而不是只信字面**
- `confidence` 相应下调（见第一条：扫描版 OCR 错误较多 → 中）

**PDF（有文字层，但提取出来是乱码）** —— 第三种 PDF 情况，**最容易踩**

- **成因**：PDF 的文字层依赖内嵌字体的 **ToUnicode 映射表**。表缺失时，`pdftotext` 取到的是**字形索引**而非汉字，输出形如 `!!)# !"`、`!'''`。
- **危险点**：`pdftotext` 的字符数**不为 0**。**任何「有字数就直接用」的判断都会静默拿到一坨垃圾 —— 而且它看着不报错。**
- **快检（与上面那句配合看）**：

```bash
pdftotext -f 1 -l 8 "书.pdf" - | tr -d '[:space:]' | grep -o '[一-龥]' | wc -l
```

  汉字数 **≈ 0** 而上面那句 `wc -c` **不为 0** → 就是这种。
- **处置**：**整体按「扫描版」办** —— 定位用扫描件页序、引文标 `OCR`、`confidence` 下调，三条全照上面那一节。**不得**因为「它有文字层」就当誊录用。

**epub**
- epub 无固定物理页，改用**章节定位**：`第X章 / 第X节 / 小节标题`。
- 若 epub 内嵌了原书页码，同时标注 `原书 P.xxx`。
- 格式：`epub 第X章·小节名 / 原书 P.xxx`（有原书页码时）
- 无原书页码时只写：`epub 第X章·小节名`
- 引用时定位到最小可识别单元（章→节→小节）。
- ⚠️ **epub 丢了卷 / 章标记怎么办**（劣质 epub 常见）：先**确认并报告损伤** —— 全文搜「第X卷」「第X章」，若一处都没有，说明结构标记缺失。此时**不要自己编章号**，改用下面两条替代定位，并在「存疑清单」里写明这是**推定结构**：
  - **首选**：小节若有数字编号，用「编号重新从 1 开始」的位置判断章界；
  - **兜底**：只给「第X卷·卷名（推定）」或「小节名」，并在存疑清单说明**章名是自拟的、不是原书标题**。
  - 结构损坏时**不得**在正文里出现看似精确的「第X章」—— 那会让读者误以为原书如此。

### 六、不掺外部知识

- 只写这本书里的内容。
- 想补充背景/对比/评价，必须单独放一节，标题为"补充说明"。
- 每条补充前加【补充】前缀。
- 示例：
  ```
  ## 补充说明
  【补充】此处的"气血互生"理论与《黄帝内经》中的论述一致，但本书未引用《内经》原文。
  ```

### 七、结尾交付三节

笔记末尾必须包含以下三节，顺序固定：

**存疑清单** — 列出拿不准的所有地方：页码不清的位置 · 认不准的字词（含【?】标记的汇总）· 术语/概念不确定的 · 归属不确定的（某段话不确定属于哪一章/哪一节）· 做过的校正（改了什么、依据是什么）

**覆盖度报告** — 如实报告：原书总章节/条目数 · 详述范围 · 略过范围及原因

**可关联主题** — 5-10 个关键词，方便日后做交叉链接。示例：`气血理论、解表药、性味归经、配伍禁忌、汤头歌诀`

### 八、深度要求（想透，不是写长）

- **每个观点要有「为什么」** — 不只写作者说了什么，还要写出他凭什么这么说：举的例子、用的数据、走的推理。**例子要落到具体**（谁、什么时候、发生了什么），落不到具体的例子等于没举
- **数据要有解读** — 数字本身不说明问题，要说清它意味着什么
- **时刻回答「所以呢」（So what）** — 这段内容对读者有什么用
- **章节之间要有联系** — 章末说明它在全书中的位置

> ⚠️ **硬约束**
> 上面第一条里的「例子要落到具体」，**细节只能来自原文**。
> **原文里没有的细节，一个字都不许补。** 宁可写「此处细节未摘录」，也不许脑补。
>
> 这一条是第六条「不掺外部知识」的镜像：**第六条管不掺外部，本条管不掺内部脑补。一外一内，两头都堵。**

以上为完整规范，所有书籍精读严格按此执行。

## 附录 A：验收六查（使用者用，**不要发给 AI**）

| # | 查什么 | 怎么判 |
|---|---|---|
| 1 | **有没有「存疑清单」** | 一条都没有 → 它在装懂。任何扫描件都不可能零疑问 |
| 2 | **抽查两个页码** | 翻原书对一下。**猜出来的数字往往差得很整齐**（比如统一 ±10），一抓一个准 |
| 3 | **有没有「覆盖度报告」** | 拿它和目录比，看漏掉的是不是"难写的那些" |
| 4 | **原文和概括分开了没** | 随便挑一段，问自己："这是书里的话，还是它的话？"分不出来就是没照规矩办 |
| 5 | **页码/位置双轨** | PDF：原书页 + PDF 页俱全且换算说得通；epub：章节目定位到最小可识别单元 |
| 6 | **它详读的是骨头，还是肉** | 翻目录问一句：详读章是否覆盖「全书地基／核心方法／行动指南」三类？**若最关键的一章只在"未覆盖内容"里出现过 → 退回** |

### 第 6 查为什么单列

第 3 查看「漏了什么」，第 6 查看「选了什么」——**一个看缺口，一个看选择，是同一件事的两面。**

**实测案例（对照同一本书的两份稿）：**

外部 AI 稿详读了什么？
- 有一章**有清晰的小节编号，好摘**
- 有一章**有现成的案例（三个故事），好写**

外部 AI 稿略过了什么？
- **全书第一章「基础概念」**——定义密集的地基，没有故事，只做了【概述】
- **全书末章「行动指南」**——**仅据章标题，一字未读**

**注意：第一章排在全书最前，它却只做概述；中间几章反而详读。** 所以不是"从头读到哪算哪"，而是**挑顺手的**。

**规律不是随机的。** AI 会滑向「哪节好摘摘哪节」：
- 概述比引原文容易得多
- 有案例、有金句的章节写出来出彩
- 逐条忠实转述（如一份 N 条的清单）又难、又容易出错，会被回避

所以翻详读章时问的是：**这是这本书的骨头，还是好啃的肉？**

> **另注（脚本的边界）**：配套的 `qc-deepread.ps1` 能查「有没有引文」「有没有存疑清单」，但**查不出"跳过了哪一章"**；输出里的「章节提及」次数也不等于精读深度（实测：被跳过的那一章在稿里仍被提及 8 次）。**这一查只能人工做。**

## 附录 B：分块喂（使用者用）

**一次喂整本书，AI 会"前面认真、后面糊弄"。** 更可靠的做法：

1. 按原书章节分批给（每批 30-60 页）
2. 每批读完**先交小结**再继续下一批
3. 全部读完后，让它自己合并成完整笔记

好处：你能从每批小结看出它是真读了还是编的 —— 编的会前后矛盾。

## 附录 C：入库前还需补的

- 补**来源类型**标注（AI 不管这个字段）
- 补**交叉链接**（可由 AI 的"可关联主题"转化）
- 登记到**索引**
- 接入对应的**领域目录**
- 剔除下载器附带的 AIGC 元数据（若 AI 用了带该标记的工具链）
